**Semantic Standardization of Unstructured Categorical Data Using Local LLMs and Retrieval-Augmented Generation: A Case Study on Industrial Tool Names**

## ABSTRACT

> *(~150 words — fits a typical poster abstract box)*

Unstructured categorical data generated by manual entry often contains severe lexical variability, making automated classification unreliable. This study proposes a Retrieval-Augmented Generation (RAG) framework employing open-source Large Language Models (LLMs) to semantically standardize industrial tool names. Using the Seoul Metropolitan Tool Rental Dataset — 3,352 unique dirty tool name strings across 160 standard categories — we evaluate 12 open-source LLMs (1.5B–9B parameters) under two RAG configurations. A baseline RAG (MiniLM-L12 embedding, FAISS top-5 retrieval) achieves ~55% accuracy, while an improved RAG — incorporating a Korean-specialized embedding model (BGE-m3-ko), BM25+FAISS hybrid retrieval, expanded candidate pool (k=15), and category-augmented prompting — reaches up to **88.47%** accuracy (gemma4:e4b), a **+33.3 percentage point** gain. Critically, prior inflated results (97.88%) are attributed to train/test data leakage; our evaluation strictly separates retrieval knowledge from ground-truth assessment. Results show that domain-optimized retrieval architecture matters more than model scale for this task.

## 1. INTRODUCTION

### Background
- In data-intensive industries, manually entered categorical fields frequently yield **"dirty data"**: inconsistent, non-standard representations of the same concept.
- Example: the 3,352 unique tool name strings in Seoul's public tool rental database map to only **~160 real tool categories** (~21 variants per category on average).
- Traditional rule-based NLP (regex, morphological analyzers) addresses only **syntactic** errors; it fails on **semantic** variability such as:
  - Japanese-derived legacy terms: *giri* (ぎり) → drill bit
  - Brand/spec attributes embedded in names: *"BOSCH 18V Cordless Drill Set"* → *drill*
  - Compound nouns, abbreviations, typos

### Problem Statement
- Manual standardization of 3,352 records requires ~3–5 expert working days.
- Rule-based automation demands hundreds of hand-crafted rules, with continuous maintenance as new entries arrive.
- **Research question:** Can an open-source LLM, augmented with a small domain-specific knowledge base via RAG, achieve practical accuracy for semantic standardization of unstructured categorical data?

### Contributions
1. **Rigorous evaluation framework** — strict separation of RAG retrieval knowledge base from ground-truth evaluation set, eliminating data leakage present in prior work.
2. **Improved RAG pipeline** — four targeted enhancements (Korean-specialized embedding, hybrid retrieval, candidate pool expansion, category injection).
3. **Comparative benchmark** — 12 open-source LLMs across baseline and improved configurations on a real-world Korean dirty-data corpus.

### 2.2 RAG Architecture

**Knowledge Base (Retrieval DB):**
- Contains only **160 standard tool names** (no original→standard mapping pairs)
- Ensures zero overlap with the evaluation ground-truth set

**Evaluation Set:**
- 457 curated `(dirty_name → standard_name)` pairs
- **Completely separate** from retrieval knowledge base

### 2.3 Configurations

| Component | Baseline | Improved |
|-----------|----------|----------|
| Embedding model | `paraphrase-multilingual-MiniLM-L12-v2` (384-dim) | `dragonkue/BGE-m3-ko` (1024-dim, Korean KURE #1) |
| Retrieval | FAISS (cosine similarity) | **BM25 (40%) + FAISS (60%) hybrid** |
| Candidate pool (k) | 5 | **15** |
| Prompt augmentation | — | **Category injection** (tool category & subcategory) |
| Fallback | LLM output → top-1 if out-of-candidate | Same |

**BM25 Korean tokenizer:** syllable unigram + bigram (e.g., *"경랑몽키"* → ['경', '랑', '몽', '키', '경랑', '랑몽', '몽키']).

**Hybrid score:**
```
score = 0.4 × BM25_norm + 0.6 × FAISS_cosine_norm
```

### 3.2 Key Findings

**① Model size does not predict performance in RAG settings**
- gemma3:4b (3.3 GB) outperforms exaone3.5:7.8b (4.8 GB): **84.5% vs. 79.2%**
- deepseek-r1:1.5b (1.1 GB) achieves 78.1% — comparable to 8B models with improved RAG
- RAG-supplied domain knowledge compensates for limited model capacity

**② Each improvement component contributes**
- BGE-m3-ko (Korean-specialized, 1024-dim) vs. MiniLM-L12 (multilingual, 384-dim): captures Korean morphological similarity (e.g., *"gyeongrang monkey"* → *monkey wrench*)
- BM25 hybrid: recovers lexical signals missed by pure semantic retrieval
- k=15 expansion: reduces forced fallback (granite4.1:8b: 14.9% → 5.0%)
- Category injection: improves disambiguation between semantically similar classes

**③ Fallback rate as a reliability indicator**
- deepseek-r1:1.5b: 85.2% fallback → model instruction-following failure (output format issues)
- granite4.1:3b: 20.8% fallback → marginal instruction compliance
- Top-3 models: 5–8% fallback — acceptable range for production

**④ Speed vs. accuracy trade-off**

| Scenario | Recommended Model | Accuracy | Speed |
|----------|------------------|---------|-------|
| Accuracy-first | gemma4:e4b | 88.47% | 1.58/s |
| Balanced | gemma3:4b | 84.48% | 1.77/s |
| Speed-first | gemma4:e2b | 80.93% | 1.93/s |

All top models process 3,352 records in **under 50 minutes** on a consumer GPU (RTX 5080).

## 4. CONCLUSION

### Summary
- We present a **RAG-based semantic standardization pipeline** for unstructured categorical dirty data, validated on real-world Korean industrial tool name records.
- Four targeted RAG improvements — Korean-specialized embedding, BM25+FAISS hybrid retrieval, expanded candidate pool (k=15), and category-augmented prompting — collectively raise accuracy from **~55% (baseline) to 88.47% (improved)**.
- Smaller models with domain-optimized retrieval achieve competitive or superior accuracy compared to larger models, demonstrating the cost-effectiveness of the proposed approach.
- We identify and correct a **data leakage flaw** in prior RAG evaluation designs, establishing a more rigorous benchmark.

### Limitations
- Ground-truth coverage: 457 / 3,352 = **13.6%** — evaluation set may not fully represent the full dirty-data distribution.
- Models >17B parameters are impractical on a single consumer GPU (RTX 5080, 17.1 GB VRAM) due to CPU offload bottleneck (~0.03 items/s).
- deepseek-r1:1.5b shows high fallback (85.2%), limiting real-world applicability despite moderate accuracy.

### Future Work
1. **Large model evaluation** (32B+) with quantization or multi-GPU inference
2. **Ground-truth expansion** to full 3,352 records for complete coverage
3. **Human-in-the-Loop** integration for low-confidence predictions (ambiguous compound tools, set items)
4. **Domain fine-tuning** comparison: RAG vs. LoRA-adapted models on tool name data
5. **Generalization study** across other dirty categorical domains (medical codes, product SKUs, job titles)
