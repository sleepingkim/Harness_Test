## 5. 해석 및 시사점

### 5.1 RAG 기여도 해석

| 구간 | 해석 |
|------|------|
| RAG 기여 +20pp 이상 | RAG가 핵심. LLM 단독으로는 실용 불가 |
| RAG 기여 +10~20pp  | RAG가 중요한 정밀도 보완 역할 |
| RAG 기여 +5~10pp   | RAG 효과 있으나 LLM 자체도 상당한 수준 |
| RAG 기여 +5pp 미만  | LLM 고유 지식이 충분. RAG의 한계 구간 존재 가능 |

### 5.2 일본어 잔재 유형 특이 분석

일본어 잔재 유형은 RAG 적용 후 정확도가 47.1%에 불과하다. 
LLM-only 결과와 비교하면 다음 중 하나가 확인될 것이다:

- **LLM-only > RAG**: BGE-m3-ko가 일본어 공구명 임베딩을 실패하여 RAG가 역효과
- **LLM-only ≈ RAG**: LLM 자체의 지식 한계가 근본 원인
- **LLM-only < RAG**: RAG가 어느 정도 보완했으나 둘 다 낮음

이 결과에 따라 일본어 잔재 유형의 해결 방향(사전 선처리 vs 임베딩 개선 vs 더 큰 LLM)이 결정된다.

### 5.3 nearest_match vs exact_match 괴리 해석

nearest_match와 exact_match의 차이가 클수록, LLM이 개념은 알고 있으나 표기가 다르게 나온다는 뜻이다.
이 경우 후처리 매핑 레이어를 추가하면 LLM-only 방식도 실용적일 수 있다.

## 6. 결론

### 결론 1. RAG는 선택이 아닌 필수 — LLM 단독으로는 실용 불가

| 모델 | LLM-only | RAG | 기여 |
|------|:---:|:---:|:---:|
| gemma4:e4b | 27.4% | 88.5% | **+61.1pp** |
| gemma3:4b | 23.0% | 84.5% | **+61.5pp** |
| exaone3.5:7.8b | 9.4% | 79.2% | **+69.7pp** |
| deepseek-r1:1.5b | 0.0%* | 78.4% | — |

전 모델에서 RAG 기여도가 **+60pp 이상**으로, LLM 단독 성능(9~27%)은 실무 적용 불가 수준이다. 표준화 작업은 표준명 후보 풀과 유사도 검색(RAG)이 없이는 LLM이 표준명을 정확히 재현할 수 없다.

> ⚠️ deepseek-r1:1.5b 0%의 실제 원인: `num_predict` 조정·`think:false`·chat API 등 모든 방법 시도 결과, 이 모델은 **한국어 자유 생성 능력 자체가 부재**함. 출력이 중국어("您好")·영어·깨진 한국어 혼합으로 나옴. 1.5B 파라미터의 영어/중국어 중심 사전학습 한계이며, 0%는 올바른 측정값임.

---

### 결론 2. 개념 이해는 있으나 표기 통일 능력이 없다 — nearest_match 괴리

```
모델               exact_match   nearest_match   괴리
gemma4:e4b           27.4%         63.2%        +35.8pp
gemma3:4b            23.0%         60.8%        +37.8pp
exaone3.5:7.8b        9.4%         60.4%        +51.0pp
```

LLM은 "드릴"이라는 개념은 알고 있다. 그러나 "전동드릴"인지 "드릴"인지 "충전 드릴"인지 표준 표기를 결정하지 못한다. RAG가 후보 풀을 제공해야 비로소 정답을 선택할 수 있다. **RAG의 역할은 LLM의 지식 보완이 아니라 표기 앵커링(anchoring)이다.**

---

### 결론 3. 동력원 명시 유형에서 RAG 기여가 가장 크다 (+88.4pp)

LLM-only에서 동력원 명시 유형의 정확도는 **8.0%**에 불과하다. "전동드릴", "유선전동드릴" 같은 입력을 받으면 LLM은 "전동 드릴", "유선 전동 드릴" 식으로 표기 그대로 출력하거나, 원본 동력원 수식어를 살린 채로 답한다. 표준명("전동드릴")으로 수렴하려면 RAG가 반드시 필요하다.

---

### 결론 4. 일본어 잔재에서 RAG는 실제로 도움이 된다 (19.0% → 47.1%)

LLM-only 일본어 잔재 정확도: **19.0%**  
RAG 적용 후: **47.1%** (+28pp)

"BGE-m3-ko가 일본어 공구명 임베딩을 실패하여 RAG가 역효과를 낼 수 있다"는 가설은 **기각**된다. RAG가 확실히 도움이 되고 있다. 그러나 47.1%라는 낮은 절대값의 근본 원인은 LLM 자체의 일본어 공구 지식 부족(19.0%)이다. 즉, **RAG가 +28pp를 기여했음에도 여전히 부족한 것**이다. 해결책은 RAG 제거가 아니라 일본어 공구 동의어 사전으로 retrieval을 보강하는 것이다.

---

### 결론 5. deepseek-r1:1.5b — RAG가 언어 한계 자체를 극복시켜 준다

deepseek-r1:1.5b의 LLM-only 결과는 **0%**이며, 이는 단순한 API 설정 문제가 아니다. `num_predict` 512·`think:false`·chat API 전환 등 가능한 모든 방법을 시도했으나, 출력이 중국어("您好", "透明是国际社会...")·영어·깨진 한국어의 혼합으로 나왔다. 이 모델은 1.5B 파라미터의 영어/중국어 중심 학습 구조상 **한국어 자유 생성 자체가 불가**하다.

그럼에도 RAG 파이프라인에서는 **78.4%**를 달성했다. 이는 RAG가 단순히 정확도를 높이는 것이 아니라, **아예 불가능했던 작업(한국어 자유 생성)을 가능한 작업(한국어 후보 중 선택)으로 전환**해 준다는 것을 보여준다. RAG의 역할이 "정밀도 보완"을 넘어 "언어 능력 한계의 우회"임을 가장 극단적으로 보여주는 사례다.

---

### 결론 6. 한국어 특화 모델(exaone)이 LLM-only에서 가장 낮다 (9.4%)

예상과 달리 한국어 특화 exaone3.5:7.8b의 LLM-only exact_match가 9.4%로 최저다. 출력 패턴을 보면 exaone은 더 많은 설명을 포함하는 경향이 있다 (예: "경량몽키렌치 (8인치)", "버니어 캘리퍼스 (300mm)"). nearest_match는 60.4%로 다른 모델과 동등하므로 개념 이해 능력 자체의 문제가 아니라, exaone이 프롬프트에 대해 더 장황한 응답 스타일을 갖는 것이 exact_match를 낮추는 원인이다.
