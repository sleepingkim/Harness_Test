## 결론 1. 이 태스크의 병목은 "지식"이 아닌 "지시 따르기" 능력

![chart1_accuracy](charts/chart1_accuracy.png)

모델 크기와 정확도를 교차 비교하면 파라미터 크기 순서가 성능 순서와 일치하지 않는다:

```
gemma3:4b  (3.3GB) → 84.48%   ← 더 작은데 이긴다
exaone3.5:7.8b (4.8GB) → 79.16%

deepseek-r1:1.5b (1.1GB) → 78.05%  ← 더 작은데 이긴다
exaone3.5:2.4b   (1.6GB) → 74.06%

deepseek-r1:8b  (5.2GB) → 77.83%  ┐
granite4.1:8b   (5.3GB) → 82.48%  ┘  비슷한 크기, 4.7%p 차이
```

**결론**: 이 태스크(15개 후보 중 하나를 JSON으로 선택)는 도메인 지식보다 **"제약 출력 형식 준수 + 후보 비교 추론"** 능력이 성능을 결정한다. Gemma 계열이 전반적으로 우수한 이유도 여기에 있다.

## 결론 3. RAG top-1 기준값 역추정 — LLM 실질 기여도 분리

deepseek-r1:1.5b의 Fallback이 85.2%라는 것은 451건 중 ~384건에서 LLM이 유효한 선택을 하지 못하고 RAG top-1이 그대로 채택됐다는 의미다.

```
deepseek-r1:1.5b 실제 동작:
  ├─ 84.8% → LLM 출력 무효 → RAG top-1 강제 채택 (사실상 RAG-only)
  └─ 15.2% → LLM이 선택 (이 중 일부는 RAG top-1 외 후보 선택)

최종 정확도: 78.05%
→ RAG top-1의 정확도 ≈ 78% (역추정)
```

이를 기준으로 **각 모델의 LLM 실질 기여도**를 계산:

| 모델               |    정확도 |              LLM 기여 (+/-) |
| ---------------- | -----: | ------------------------: |
| gemma4:e4b       | 88.47% |               **+10.5%p** |
| gemma3:4b        | 84.48% |                **+6.5%p** |
| granite4.1:8b    | 82.48% |                **+4.5%p** |
| gemma4:e2b       | 80.93% |                **+2.9%p** |
| exaone3.5:7.8b   | 79.16% |                **+1.2%p** |
| deepseek-r1:1.5b | 78.05% |       ≈ 0%p (RAG-only 수준) |
| deepseek-r1:8b   | 77.83% |                **-0.2%p** |
| exaone3.5:2.4b   | 74.06% |                **-3.9%p** |
| granite4.1:3b    | 67.85% | **-10.2%p** (LLM이 오히려 방해) |

![chart4_llm_contribution](charts/chart4_llm_contribution.png)

**시사점**: granite4.1:3b는 LLM 없이 RAG top-1만 쓰는 게 더 정확하다. "더 좋은 LLM"과 "더 나쁜 LLM"이 공존하며, 기준보다 못한 모델은 시스템 성능을 저해한다.

## 결론 4. RAG 구조가 모든 모델의 공통 하한선을 형성한다

![chart3_error_breakdown](charts/chart3_error_breakdown.png)

```
9개 모델 모두: RAG 후보 누락 ≈ 25건 (고정)

이론적 최대 정확도 = (451 - 25) / 451 × 100 = 94.5%

현재 최고 모델 (gemma4:e4b) = 88.47%
이론적 최대까지 남은 격차   = 6.0%p
  └─ 이 중 대부분: LLM 오선택 24건 (추론 문제)
```

| 개선 대상 | 개선 방법 | 기대 효과 |
|---------|---------|---------|
| RAG 구조 문제 (~25건) | 일본어 사전, 오탈자 전처리 추가 | 모든 모델 공통 +5~8%p |
| LLM 오선택 (모델별) | 세트/단품·동력원 특화 프롬프트 | 상위 모델 추가 +2~4%p |

**핵심**: RAG 개선은 모든 모델에 동시에 효과가 나타나므로, **ROI 관점에서 LLM 교체보다 RAG 개선이 먼저다.**

## 결론 5. 더티데이터 유형이 성능 격차를 설명한다

정답지 v2(457쌍)를 11개 더티데이터 유형으로 자동 분류하고 유형별 정확도를 산출하였다. 결과는 RAG의 성공과 실패 원인을 유형 단위로 설명해준다.

### 유형별 정확도 — gemma4:e4b(최고 모델) 기준

| 유형 | 정확도 | 정답/전체 | 수준 |
|------|:------:|:--------:|:----:|
| 동력원 명시 (n=55) | **96.4%** | 53/55 | 우수 |
| 메타데이터 (n=22) | **95.5%** | 21/22 | 우수 |
| 속성 기입 (n=40) | **95.0%** | 38/40 | 우수 |
| 오탈자 (n=145) | **93.8%** | 136/145 | 우수 — 최다 빈도(33.9%) |
| 브랜드 혼입 (n=72) | 87.5% | 63/72 | 양호 |
| 세트/구성품 (n=26) | 84.6% | 22/26 | 양호 |
| 영문/약어 (n=40) | 82.5% | 33/40 | 양호 |
| 기타 (n=27) | 66.7% | 18/27 | 취약 |
| **일본어 잔재 (n=17)** | **47.1%** | **8/17** | **위험** |

### 오탈자 93.8%가 핵심 성과인 이유

오탈자는 전체 GT의 33.9%로 가장 많은 유형이면서 93.8% 정확도를 달성했다. 이것이 개선 RAG의 가장 큰 기여다. BGE-m3-ko(1024-dim, KURE 1위)는 한국어 형태소 변이를 벡터 공간에서 가깝게 인코딩하여 오탈자-표준명 간 유사도를 높게 계산한다. Baseline(MiniLM-L12, 384-dim)에서 같은 유형이 ~55%였던 것과 비교하면 **BGE-m3-ko 교체가 오탈자 유형에서 +38pp를 견인**하며, 이것이 전체 평균 개선(55% → 79%)의 가장 큰 단일 기여 요인이다.

### 일본어 잔재 47.1% — 결론 4와 연결되는 구조적 원인

RAG 후보 누락(~25건) 중 가장 큰 기여 유형이 일본어 잔재다. 세 가지 이유로 FAISS와 BM25 모두 실패한다:

| 실패 단계 | 원인 |
|---------|------|
| FAISS (의미 검색) | `기리` ↔ `드릴비트`: 발음 완전 다름 → 벡터 유사도 낮음 |
| BM25 (어휘 검색) | `기리`(기,리,기리) ↔ `드릴비트`(드,릴,비,트,...): 공통 n-gram 없음 |
| LLM 선택 | 사전학습 코퍼스에 `기리=드릴비트` 매핑 희소 → 후보 선택 실패 |

모든 9개 모델이 23.5~52.9%로 일관되게 낮아, **모델 교체로는 해결 불가한 RAG 아키텍처 구조 문제**임이 확인된다. 해결책: 일본어→한국어 공구 동의어 사전을 RAG 지식베이스에 명시 주입.

### 교차 분석 이상치

- **세트/구성품**: exaone3.5:7.8b가 96.2%로 1위 (gemma4:e4b 84.6% 대비 +11.6pp). EXAONE의 한국 산업 현장 동의어 지식 우위(L렌치=육각렌치 등).
- **속성 기입**: granite4.1:3b가 50.0%로 이상 저조. 3B 소형 모델이 규격 수치 포함 프롬프트에서 후보 선택 판단력 부족.

## 결론 8. LLM-only 비교 실험 — RAG 기여도 정량화

LLM-only Zero-shot 실험 결과 (2026-05-09, GT 457건):

| 모델 | LLM-only | RAG | 기여 |
|------|:---:|:---:|:---:|
| gemma4:e4b | 27.4% | 88.5% | +61.1pp |
| gemma3:4b | 23.0% | 84.5% | +61.5pp |
| exaone3.5:7.8b | 9.4% | 79.2% | +69.7pp |
| deepseek-r1:1.5b | 0% | 78.4% | +78.4pp |

핵심 발견 4가지:
1. RAG 기여도 +60~70pp: LLM 단독(최고 27.4%)은 실용 불가 수준
2. RAG 역할 = 표기 앵커링: exact(27%) vs nearest(63%)의 35pp 괴리가 보여주듯, LLM은 개념은 알지만 표기를 통일하지 못함. RAG가 후보 풀을 제공해야만 표기가 수렴됨
3. deepseek-r1:1.5b: 한국어 자유 생성 자체 불가(0%), RAG로 78.4% 달성 → RAG가 언어 능력 한계 자체를 우회하는 역할
4. 일본어 잔재 RAG 역효과 기각: LLM-only 19.0% → RAG 47.1% (+28pp). RAG는 일본어 유형에서도 도움이 됨. 47.1% 절대값이 낮은 것은 LLM 지식 한계(19%)가 근본 원인

종합: RAG는 "정밀도 보완" 이상의 역할을 한다. 한국어 생성 자체가 불가능한 모델도 실용적 수준(78%)으로 끌어올린다는 점에서, 이 아키텍처의 핵심 가치는 RAG의 후보 앵커링에 있다.
