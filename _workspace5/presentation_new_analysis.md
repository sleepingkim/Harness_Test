## 분석 1. 더티데이터 유형별 정확도 분석

---

### 1-1. 방법 — 유형 분류 방법론

- **방식:** 휴리스틱 규칙 기반 자동 분류 (Python 스크립트)
- **적용 순서 (우선순위 순):**

```
인코딩 오류 → 운영용 텍스트 → 메타데이터 → 일본어 잔재
→ 브랜드 혼입 → 동력원 명시 → 영문/약어 → 특수기호
→ 세트/구성품 → 속성 기입 → 오탈자 → 기타
```

- 각 공구명은 우선순위가 가장 높은 규칙 하나의 유형으로만 분류됨

---

### 1-2. 결과 — GT 457건 유형 분포

| 유형 | 건수 | 비율 |
|------|:---:|:---:|
| 오탈자 | 155 | 33.9% |
| 브랜드 혼입 | 71 | 15.5% |
| 동력원 명시 | 50 | 10.9% |
| 영문/약어 | 41 | 9.0% |
| 속성 기입 | 40 | 8.8% |
| 기타 | 27 | 5.9% |
| 세트/구성품 | 23 | 5.0% |
| 메타데이터 | 22 | 4.8% |
| 일본어 잔재 | 21 | 4.6% |

> 오탈자(33.9%)가 압도적 다수. 일본어 잔재는 건수는 적지만 정확도 측면에서 핵심 문제 유형.

---

### 1-3. 결과 — 최고 모델(gemma4:e4b) 유형별 정확도

| 유형 | 정확도 | 오답 건수 |
|------|:---:|:---:|
| 동력원 명시 | **96.4%** | 2건 |
| 메타데이터 | **95.5%** | 1건 |
| 속성 기입 | **95.0%** | 2건 |
| 오탈자 | 93.8% | 9건 |
| 브랜드 혼입 | 87.5% | 9건 |
| 세트/구성품 | 84.6% | 4건 |
| 영문/약어 | 82.5% | 7건 |
| 기타 | 66.7% | 9건 |
| 일본어 잔재 | **47.1%** | 9건 |

> 전체 88.5% 뒤에 **47% ~ 96%의 유형별 변동**이 숨어있음. 일본어 잔재가 유일한 취약 영역.

---

### 1-4. 결과 — 9개 모델 × 유형별 교차 정확도 (핵심 수치)

| 유형 | e4b | 3:4b | gn8 | e2b | ex7 | ds8 | ds1 | ex2 | gn3 |
|------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 동력원 명시 | **96.4** | 85.5 | 87.3 | 83.6 | 78.2 | 81.8 | 81.1 | 78.2 | 74.5 |
| 속성 기입 | **95.0** | 92.5 | 82.5 | 92.5 | 85.0 | 80.0 | 85.0 | 80.0 | 50.0 |
| 오탈자 | **93.8** | 88.3 | 93.1 | 80.7 | 82.1 | 85.5 | 88.3 | 86.2 | 71.7 |
| 세트/구성품 | 84.6 | 88.5 | 84.6 | 84.6 | **96.2** | 80.8 | 84.6 | 84.6 | 61.5 |
| 일본어 잔재 | 47.1 | **52.9** | 41.2 | 23.5 | 47.1 | 29.4 | 35.3 | 23.5 | 23.5 |

> 모델 약어: e4b=gemma4:e4b, 3:4b=gemma3:4b, gn8=granite4.1:8b, e2b=gemma4:e2b, ex7=exaone3.5:7.8b, ds8=deepseek-r1:8b, ds1=deepseek-r1:1.5b, ex2=exaone3.5:2.4b, gn3=granite4.1:3b

**주목할 이상값:**
- **exaone3.5:7.8b (ex7)**: 전체 5위(79.2%)임에도 **세트/구성품에서만 96.2%로 1위**
- **granite4.1:3b (gn3)**: 속성 기입 유형에서 다른 모델이 80%+를 달성하는 동안 **50.0%에 그침**

---

### 1-5. 해석 — 유형별 성능 메커니즘

**오탈자 93.8% — 우수 원인**
- BGE-m3-ko 임베딩이 음절 수준 유사도를 포착
- 'ㅐ↔ㅔ 혼용', '경랑→경량' 같은 철자 오류에서도 retrieval 성공
- 임베딩 모델의 한국어 오탈자 내성이 성능을 견인

**일본어 잔재 47.1% — 취약 원인 (3중 장벽)**

| 장벽 | 설명 |
|------|------|
| Retrieval 실패 | BGE-m3-ko가 '기리'(드릴의 일본어)를 '드릴'과 연결하지 못함 |
| LLM 지식 부재 | 오픈소스 LLM의 일본어 공구 용어 지식 미흡 |
| 역번역 불가 | 문맥 없이 일본어 공구명만으로 표준명 추론 불가 |

**세트/구성품 — exaone3.5:7.8b 이상값**
- 전체 순위 5위 모델이 이 유형에서만 1위(96.2%)
- 한국 산업 현장의 복합 공구 세트 명칭에 특화된 사전학습 지식 보유 추정
- 유형별 분석 없이는 발견 불가능한 모델 특성

**granite4.1:3b 속성 기입 50%**
- 다른 모델이 80~95%를 달성하는 유형에서 절반 수준
- 소형 IBM 모델의 한국어 속성(용량·규격 등) 분리 능력 한계

## 분석 2. LLM-only Zero-shot 비교 실험

---

### 2-1. 방법 — 실험 설계

| 항목 | 내용 |
|------|------|
| 목적 | RAG의 실질 기여도 정량화 (비교 기준선 확보) |
| 방식 | RAG 없이 LLM 자체 지식만으로 표준화 시도 (Zero-shot) |
| 프롬프트 | "비표준 공구명을 표준 한국어 공구명으로 변환하세요. 표준 공구명만 출력하세요." |
| 평가 지표 1 | **exact_match** — 출력이 정답과 완전히 일치 |
| 평가 지표 2 | **nearest_match** — 표준명 리스트 내 최근접 후보로 매핑 후 일치 여부 |
| 평가 대상 | GT 457건, 4개 모델 선정 |

**선정 모델:** gemma4:e4b, gemma3:4b, exaone3.5:7.8b, deepseek-r1:1.5b

> nearest_match는 "LLM이 개념은 알고 있으나 표기가 다를 때"를 별도 측정하기 위한 지표.

---

### 2-2. 결과 — 전체 비교

| 모델 | LLM-only exact | LLM-only nearest | RAG v2 | RAG 기여 |
|------|:---:|:---:|:---:|:---:|
| gemma4:e4b | 27.4% | 63.2% | 88.5% | **+61.1pp** |
| gemma3:4b | 23.0% | 60.8% | 84.5% | **+61.5pp** |
| exaone3.5:7.8b | 9.4% | 60.4% | 79.2% | **+69.7pp** |
| deepseek-r1:1.5b | **0%** | 0.7% | 78.4% | **+78.4pp** |

> 모든 모델에서 RAG 기여가 +61pp 이상. deepseek-r1:1.5b는 LLM-only에서 사실상 동작 불가 → RAG로 78.4% 달성.

---

### 2-3. 결과 — 유형별 비교 (gemma4:e4b 기준)

| 유형 | LLM-only | RAG v2 | RAG 기여 |
|------|:---:|:---:|:---:|
| 동력원 명시 | 8.0% | 96.4% | **+88.4pp** |
| 오탈자 | 21.9% | 93.8% | **+71.9pp** |
| 일본어 잔재 | 19.0% | 47.1% | **+28.0pp** |
| 속성 기입 | 55.0% | 95.0% | **+40.0pp** |
| 메타데이터 | 45.5% | 95.5% | **+50.0pp** |

> RAG 기여 편차: 최소 +28pp (일본어 잔재) ~ 최대 +88pp (동력원 명시). 어느 유형에서도 RAG가 역효과를 내지 않음.

---

### 2-4. 해석 — 핵심 발견 3가지

---

**① RAG의 역할 = "표기 앵커링"**

```
exact_match  27.4%
                    ↕ 35pp 괴리
nearest_match 63.2%
```

- LLM은 "드릴"이라는 **개념**은 알지만, 정답이 "전동드릴"인지 "드릴"인지 "충전드릴"인지 결정하지 못함
- RAG가 15개 후보 풀을 제공하는 순간 표기가 수렴됨
- **결론: RAG는 "지식 보완"이 아니라 "표기 결정자" 역할을 함**

---

**② deepseek-r1:1.5b — RAG가 언어 능력 한계를 우회**

| 조건 | 결과 |
|------|------|
| LLM-only | 0% (출력이 중국어·영어·깨진 한국어 혼합) |
| RAG v2 | **78.4%** |

- 한국어 자유 생성 능력 자체가 없는 모델
- RAG 적용 시 태스크가 "한국어 자유 생성" → **"15개 한국어 후보 중 선택"** 으로 전환
- **결론: RAG가 불가능한 작업을 실용적 수준으로 바꿈**

---

**③ 일본어 잔재 — "RAG 역효과" 가설 기각**

| 가설 | "BGE-m3-ko가 일본어 공구명을 잘못 임베딩하여 RAG가 오히려 방해할 수 있다" |
|------|------|
| 검증 결과 | LLM-only 19.0% → RAG 47.1% (**+28pp 향상**) |
| 결론 | RAG는 일본어 잔재 유형에서도 기여함 |

- 47.1%라는 낮은 절대값의 원인은 RAG가 아님
- **원인: LLM 자체의 일본어 공구 용어 지식 부재**
- 해결 방향: RAG 개선이 아닌 **전처리 동의어 사전** (기리→드릴 등) 추가

## 종합 시사점

---

### 시사점 1 — 유형 기반 오류 진단이 가능하다

- 전체 정확도 88.5% 뒤에 숨어있던 **유형별 변동(47% ~ 96%)** 가시화
- 막연한 "성능 개선" 대신 **개선 포인트를 특정** 가능
- 유형 분류 → 타겟 개선 → 재측정 사이클 수립 가능

---

### 시사점 2 — RAG는 표기 앵커로서 구조적으로 필수적이다

| 구분 | 수치 |
|------|:---:|
| LLM-only 최고 성능 | 27.4% |
| RAG v2 최고 성능 | 88.5% |
| 향상 | **+61.1pp** |

- 단순 정밀도 보완이 아닌 **구조적 역할**: 후보 집합 제공 → 표기 결정
- 소형 모델도 RAG를 통해 대형 모델 수준에 근접 가능

---

### 시사점 3 — 우선 개선 대상 명확: 일본어 잔재

| 지표 | 수치 |
|------|:---:|
| 현재 정확도 | 47.1% |
| RAG 기여 | +28pp (기여하고 있음) |
| 병목 원인 | LLM 지식 부재 |
| 개선 방향 | 전처리 동의어 사전 추가 (기리→드릴, 노미→끌 등) |

- 동의어 사전 추가 시 Retrieval 단계에서 표준 공구명과 연결 가능
- 47.1% → 70%+ 수준 개선 기대
