# 더티데이터 유형별 정제 성능 분석 보고서

> **분석 대상:** 서울시 공구대여 데이터셋 공구명 표준화 — RAG v2 Improved  
> **평가 기반:** 정답지 v2 (457쌍) × 9개 모델 checkpoint  
> **작성 기준:** 2026-05-09

---

## 1. 분석 개요

### 1.1 목적

본 분석은 LLM+RAG 기반 공구명 표준화 시스템이 **더티데이터 유형별로 성능 차이를 보이는 원인**을 규명하고, 유형 특성과 정확도 결과의 관계를 수치와 사례로 해석하는 것을 목적으로 한다.

RAG v2 Improved 파이프라인(BGE-m3-ko 임베딩 + BM25/FAISS 하이브리드 + k=15 + 카테고리 주입)을 적용한 9개 모델의 checkpoint 파일을 정답지 v2(457쌍)와 매핑하여 유형별 정확도를 산출하였다.

### 1.2 분석 파이프라인

```
표준명 정답지 v2 (457쌍)
  └─ 유형 자동 분류 (휴리스틱 규칙 기반)
       └─ 각 모델 checkpoint (9종)과 병합
            └─ dirty_type × model 교차 정확도 계산
                 └─ 차트 + Excel + 해석 문서 생성
```

**유형 분류 우선순위** (동일 입력명이 복수 유형 조건 충족 시 우선 적용):
인코딩 오류 → 운영용 텍스트 → 메타데이터 → 일본어 잔재 → 브랜드 혼입 → 동력원 명시 → 영문/약어 → 특수기호 → 세트/구성품 → 속성 기입 → 복합명사 → 오탈자 → 기타

## 5. 유형별 상세 해석

### 5.1 쉬운 유형 (90%+): "어노테이션 제거 후 핵심어가 명확한 패턴"

---

#### ① 동력원 명시 — 96.4% (오답 2/55건)

**유형 특성:** 공구명에 동력 방식(유선/충전/전동/무선/에어/배터리 등)이 수식어로 포함된 경우

**실제 사례:**

| 입력(더티) | 표준명 | 변환 핵심 |
|-----------|--------|---------|
| 유선전동드릴 | 전동드릴 | "유선" 제거 |
| 전동드릴(유선) | 전동드릴 | 괄호 속 동력원 제거 |
| (20)유선 전동드릴 | 전동드릴 | 숫자+동력원 제거 |
| 충전함마드릴(디월트) | 충전해머드릴 | "충전" 유지 + 브랜드 제거 |

**왜 잘 되는가:**

동력원 키워드는 수식어 역할에 그치며, 핵심 공구명(드릴, 해머드릴, 그라인더 등)이 문자열에 그대로 남는다. BGE-m3-ko 임베딩은 수식어가 붙은 문자열과 핵심 표준명 사이의 의미적 거리를 좁게 계산한다. 단 "충전" 동력원은 표준명에도 포함되는 경우(충전드릴, 충전해머드릴)가 있어, 수식어 제거 vs. 유지를 올바르게 판단해야 한다. 오답 2건은 이 경계 사례에서 발생한 것으로 추정된다.

**히트맵 관찰:** 모든 모델이 74.5~96.4% 범위에 위치하며, 모델 규모와 무관하게 비교적 고르게 높은 성능을 보인다.

---

#### ② 메타데이터 — 95.5% (오답 1/22건)

**유형 특성:** 공구명 앞뒤에 숫자 태그, 상태 주석, 분류 코드 등이 붙은 경우

**실제 사례:**

| 입력(더티) | 표준명 | 메타데이터 패턴 |
|-----------|--------|--------------|
| (40)철기리 세트 | 철공용드릴비트세트 | 숫자 태그 (40) |
| 12P 3종 기리세트 | 드릴비트세트 | 수량 정보 |
| (불가) 앵글그라인더 | 앵글그라인더 | 상태 주석 |

**왜 잘 되는가:**

메타데이터 패턴(숫자, 괄호, 상태어)은 정규표현식으로 감지 가능하며 제거하면 핵심 공구명이 드러난다. LLM이 프롬프트에서 "후보 목록 중 가장 적합한 공구명을 선택하라"는 지시를 받았을 때, 숫자나 상태 태그는 공구 정체성과 무관하다고 판단하여 무시한다. granite4.1:3b와 여러 모델에서 동일하게 90.9%를 기록한 것은 이 유형이 모델 역량보다 RAG 후보 품질에 더 의존적임을 시사한다.

---

#### ③ 속성 기입 — 95.0% (오답 2/40건)

**유형 특성:** 규격·크기·용량 수치(mm, V, kg 등)가 포함된 공구명

**실제 사례:**

| 입력(더티) | 표준명 | 속성 패턴 |
|-----------|--------|---------|
| 180mm 그라인더 | 앵글그라인더 | 크기 수치 |
| 드릴비트 8mm | 드릴비트 | 직경 수치 |
| 20V 충전드릴 | 충전드릴 | 전압 수치 |

**왜 잘 되는가:**

수치 속성은 공구 **종류**를 결정하는 것이 아니라 **규격**을 나타낸다. "180mm 그라인더"와 "앵글그라인더"는 의미적으로 동일하므로, 임베딩 공간에서 거리가 가깝다. 단, 속성이 공구를 세부 분류하는 경우(예: 드릴비트 규격별 표준명 차이)에는 오판이 발생한다.

**주목 이상치:** granite4.1:3b가 이 유형에서 **50.0%**로 현저히 낮다. 소형 모델(3B)이 규격 수치를 포함한 프롬프트에서 후보 중 최적 표준명을 선택하는 판단력이 부족함을 보여주며, 3B 이하 모델 사용 시 속성 기입 유형의 전처리(수치 제거 후 임베딩)가 필요할 수 있다.

---

#### ④ 오탈자 — 93.8% (오답 9/145건) ← **핵심 성과**

**유형 특성:** 비표준 철자, 공백 누락, 받침 오류 등 입력 오류가 포함된 공구명

**실제 사례:**

| 입력(더티) | 표준명 | 오탈자 패턴 |
|-----------|--------|----------|
| 경랑몽키 | 경량 몽키렌치 | 자음 오기 (랑→량) |
| 인버터용접기 | 인버터 용접기 | 공백 누락 |
| 스판너 | 스패너 | 모음 오기 (판→패) |
| 막치 | 망치 | 음소 탈락 |

**왜 잘 되는가 (이 연구에서 가장 중요한 발견):**

오탈자 유형은 전체 GT의 **33.9%로 가장 많은 유형**임에도 93.8%라는 높은 정확도를 달성하였다. 이는 개선된 RAG의 핵심 구성요소인 **BGE-m3-ko 임베딩**의 역할로 설명된다.

BGE-m3-ko(dragonkue/BGE-m3-ko)는 KURE 한국어 임베딩 벤치마크 1위 모델로, 1024차원 고밀도 벡터 공간에서 한국어 형태소 변이를 같은 의미로 인코딩한다. 구체적으로:

- "경랑"(오타) ↔ "경량"(정타): 음절 차이가 한 글자이며, 두 글자가 의미적으로 연관되어 있어 임베딩 벡터가 유사하다.
- BM25의 음절 unigram+bigram 인덱스도 오탈자와 표준명 사이에 공통 n-gram이 존재하면 스코어를 부여한다.

비교: Baseline RAG(MiniLM-L12, 384-dim 다국어 모델)에서는 동일 오탈자 유형에서 정확도가 ~55%대로 떨어진 반면, 개선 후 93.8%를 달성하였다. **이 유형에서의 38pp 개선이 전체 시스템 개선의 가장 큰 기여 요인이다.**

**모델 간 변동폭:** gemma4:e4b 93.8% vs. granite4.1:3b 71.7% — 22.1pp 격차. 오탈자 후보를 올바르게 선택하는 LLM의 지시 이해력 차이가 반영된다.

| 보쉬전동드릴             | 전동드릴 | "보쉬" 완전 제거              |
| 전동드릴(보쉬 GSR14.4-2) | 충전드릴 | 브랜드+모델번호 제거, "충전" 속성 추론 |
| 보쉬 충전드릴            | 충전드릴 | "보쉬" 제거, "충전" 유지        |

**왜 오답이 발생하는가:**

1. **동력원 속성 추론 실패**: `"전동드릴(무선, 보쉬)"` → 표준명은 `"충전드릴"`. 브랜드와 동력원이 동시에 혼재할 때, LLM이 "무선" 키워드를 "충전"으로 해석하지 못하면 오답이 된다.
2. **덜 알려진 브랜드**: 메보(MEBO), 세신, 계양 등 중소 브랜드는 LLM 사전학습 데이터에 드물어 브랜드 여부 자체를 인식하지 못할 수 있다.
3. **브랜드 전용 제품명**: `"보쉬 SDS-PLUS"` → 브랜드 제거 후 "SDS-PLUS"만 남으면 영문/약어 문제로 전이된다.

**모델 간 특이사항:** gemma4:e4b(87.5%)가 가장 높고, exaone3.5:2.4b(68.1%)가 가장 낮다. 브랜드 인식은 모델이 사전에 학습한 세계 지식에 의존하므로, 규모와 학습 데이터 다양성이 중요하게 작용한다.

---

#### ⑥ 세트/구성품 — 84.6% (오답 4/26건)

**유형 특성:** 공구 세트, 구성품 묶음, 키트가 포함된 명칭

**실제 사례:**

| 입력(더티)       | 표준명    | 변환 핵심             |
| ------------ | ------ | ----------------- |
| 8피스 플라이어세트   | 플라이어세트 | 수량 제거             |
| L렌치세트(9pcs)  | 육각렌치세트 | L렌치 = 육각렌치 동의어 처리 |
| 6각렌치세트 9개    | 육각렌치세트 | "6각" → "육각" 변환    |
| 가정용 미니드릴 Set | 충전드릴   | Set는 영어, 세트 의미    |

**왜 오답이 발생하는가:**

세트/구성품 유형의 핵심 난제는 **동의어 맵핑 + 세트 단위 판단**이다:
- `"L렌치"` = `"육각렌치"`: 현장 약칭과 표준명의 연결이 필요하다. RAG가 k=15 안에 "육각렌치세트"를 포함시키더라도 LLM이 L렌치=육각렌치임을 알아야 선택할 수 있다.
- 세트 구성의 범주 경계가 모호: `"드릴세트"`가 "전동드릴세트"인지 "드릴비트세트"인지 단독으로 판단이 어렵다.

**모델 간 특이사항 (히트맵 최대 이상치):** exaone3.5:7.8b가 이 유형에서 **96.2%**로 1위. gemma4:e4b(84.6%)보다 11.6pp 높다. EXAONE은 LG AI Research의 한국어 특화 모델로, 한국 산업 현장 용어(L렌치, 육각렌치 동의어 관계 등)를 사전학습 단계에서 더 많이 학습한 것으로 해석된다.

---

#### ⑦ 영문/약어 — 82.5% (오답 7/40건)

**유형 특성:** 영문자 3자 이상 또는 영문 약어(HSS, SDS, USB, LED 등)가 포함된 공구명

**실제 사례:**

| 입력(더티) | 표준명 | 변환 핵심 |
|-----------|--------|---------|
| HSS 드릴비트 | 드릴비트 | HSS = 재질명(High Speed Steel) 제거 |
| SDS 기리 | SDS드릴비트 | SDS(규격) 유지 + 기리→드릴비트 |
| PIPE렌치 | 파이프렌치 | 영문→한글 변환 |
| usb 충전식 드라이버 | 전동드라이버 | USB(인터페이스) 제거 |

**왜 오답이 발생하는가:**

1. **교차언어 임베딩 약점**: 한국어 임베딩 공간에서 영어 약어의 의미 표현이 상대적으로 약하다. `"HSS"`가 `"High Speed Steel"` 즉 **제거해야 할 재질 속성**임을 임베딩이 포착하지 못한다.
2. **약어의 유지 vs. 제거 판단**: `"SDS"`는 표준명에 남아야 하지만 `"HSS"`는 제거해야 한다. 이 판단은 규칙이 아닌 도메인 지식이 필요하다.
3. **BM25 n-gram 불일치**: 영문자 "PIPE"의 한글 발음 "파이프"는 n-gram 공유가 없어 BM25가 연결하지 못한다. 순수 의미 기반 FAISS에 의존해야 한다.

**모델 간 특이사항:** gemma4:e2b(85.0%)가 gemma4:e4b(82.5%)보다 높다. 소형 edge 모델이 영문 약어 처리에서 오히려 더 좋은 결과를 내는 것은, e4b가 더 다양한 후보 중 망설이는 반면 e2b가 단순 패턴 매칭을 더 직관적으로 수행하기 때문으로 추정된다.

### 5.3 어려운 유형 (65~80% 미만): "의미 매핑이 비선형적"

#### ⑧ 기타 — 66.7% (오답 9/27건)

**유형 특성:** 위 10개 유형 어디에도 속하지 않는 나머지 케이스

**유형 기타가 어려운 이유:**

- **정의상 다양성**: "기타"는 단일 패턴이 없다. 매우 짧은 이름, 불완전한 문자열, 여러 유형이 복합된 케이스 등 다양한 형태가 혼재한다.
- **임베딩 앵커 부재**: 명확한 키워드가 없으면 BGE-m3-ko도 가장 가까운 표준명을 찾을 단서가 부족하다.
- **LLM 추측 한계**: 카테고리 주입(category injection)이 있어도 공구 카테고리를 특정할 수 없으면 추측에 의존하게 된다.

**모델 간 특이사항:** exaone3.5:7.8b가 70.4%로 최고이지만, exaone3.5:2.4b는 44.4%로 최저. 동일 계열 모델에서 7.8B와 2.4B 간 26pp 격차는 "기타" 유형에서 모델 규모의 영향이 크게 나타남을 의미한다.

#### ⑨ 일본어 잔재 — 47.1% (오답 9/17건) ← **최대 약점**

**유형 특성:** 일제강점기 이후 건설·공구 현장에서 남아있는 일본어 차용어 기반 공구명

**실제 사례:**

| 입력(더티) | 표준명 | 변환 필요 지식 |
|-----------|--------|--------------|
| 함마드릴 | 해머드릴 | 함마(ハンマー) → 해머 |
| 기리세트 | 드릴비트세트 | 기리(錐/キリ) → 드릴비트 |
| 기리셋트 | 드릴비트세트 | 기리 + 오탈자(셋트) |
| 빠루망치 | 빠루망치 | 유지 (표준명도 빠루) |
| 니빠 | 니퍼 | 니빠(ニッパー) → 니퍼 |
| 뺀치 | 펜치 | 뺀치(ペンチ) → 펜치 |

**왜 47.1%로 가장 어려운가 — 3가지 실패 원인:**

**원인 1: 음운적 단절 (임베딩 실패)**

```
"기리" (일본어 차용, 4바이트)  
  ≠ "드릴비트" (한국어 표준, 15바이트)
```

두 문자열은 의미는 동일하지만 발음·형태가 완전히 다른 언어에서 기원한다. BGE-m3-ko가 아무리 강력한 한국어 임베딩이라도, 두 단어의 의미 동치를 학습하려면 해당 매핑이 코퍼스에 충분히 등장해야 한다. 현대 한국어 NLP 코퍼스는 "기리=드릴비트"라는 연결을 거의 포함하지 않아 임베딩 벡터가 완전히 분리된다.

**원인 2: BM25 n-gram 완전 불일치 (어휘 검색 실패)**

| 문자열 | 음절 unigram | 음절 bigram |
|--------|-------------|------------|
| 기리 | 기, 리 | 기리 |
| 드릴비트 | 드, 릴, 비, 트 | 드릴, 릴비, 비트 |
| **공통** | **없음** | **없음** |

BM25 하이브리드 검색의 40% 가중치 부분이 이 유형에서는 완전히 무력화된다.

**원인 3: LLM 도메인 지식 부재 (선택 실패)**

RAG가 운 좋게 "드릴비트"를 k=15 후보 안에 포함시키더라도, LLM이 `"기리"` → `"드릴비트"` 연결을 알지 못하면 엉뚱한 후보를 선택한다. 이 매핑은 명시적 사전 지식(일본어 건설 은어 사전)을 필요로 한다.

**모델 간 분포:**

| 모델 | 정확도 | 특이사항 |
|------|:------:|---------|
| gemma3:4b | **52.9%** | 최고 — 일본어 차용어에 상대적으로 민감한 사전학습 데이터 추정 |
| gemma4:e4b | 47.1% | 2위 |
| exaone3.5:7.8b | 47.1% | 공동 2위 |
| deepseek-r1:1.5b | 35.3% | — |
| deepseek-r1:8b | 29.4% | 파라미터 8B임에도 하위권 |
| gemma4:e2b | 23.5% | — |
| exaone3.5:2.4b | 23.5% | — |
| granite4.1:3b | 23.5% | — |
| granite4.1:8b | 41.2% | — |

모든 모델이 47% 이하(gemma3:4b 제외)라는 사실은 이것이 **모델 선택의 문제가 아니라 RAG 아키텍처의 구조적 한계**임을 보여준다.

## 7. 개선 방향 제언

### 7.1 일본어 잔재 (47.1%) — 도메인 사전 명시적 주입

현재 RAG 지식베이스는 160개 표준명만 포함한다. 일본어 잔재 해결을 위한 두 가지 접근:

**Option A: 동의어 매핑 테이블 추가 (권장)**
```
RAG 지식베이스에 추가:
기리 → 드릴비트
함마 → 해머
니빠 → 니퍼
빠루 → 빠루 (현장 표준으로 유지)
뺀치/빤치 → 펜치
겐나와 → 둥근톱/환경톱
구루마 → 운반차/핸드카
```
이 매핑을 지식베이스에 추가하면 BM25 인덱스와 임베딩 후보 풀 모두 개선된다.

**Option B: 프롬프트 내 힌트 주입**
```
Japanese-derived tool slang table: 기리=드릴비트, 함마=해머, ...
```
단, 프롬프트 길이 증가와 토큰 비용이 단점이다.

### 7.2 기타 (66.7%) — Human-in-the-Loop 큐잉

패턴이 없는 "기타" 유형은 LLM 판단의 불확실성이 높다. LLM 신뢰도 점수(confidence score) 또는 fallback 여부를 기준으로 임계값 이하 케이스를 자동으로 전문가 검토 큐로 분류하는 하이브리드 처리가 실용적이다.

### 7.3 영문/약어 (82.5%) — BM25 영문 토크나이저 보강

현재 BM25는 한국어 음절 bigram 기반이다. 영문 약어 처리를 위해 **영문 서브워드(BPE) 토크나이저**를 병렬 적용하면 "PIPE" ↔ "파이프" 같은 교차언어 어휘 검색이 가능해진다.
