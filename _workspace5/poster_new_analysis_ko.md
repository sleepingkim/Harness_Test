# LLM+RAG 공구명 표준화: 더티데이터 유형 분석 및 LLM 단독 성능 비교

> **서울시 공구대여 데이터셋 — RAG v2 Improved 추가 분석**  
> 정답지 v2 (GT 457쌍) | 평가일: 2026-05-09

---

## Abstract

서울시 공구대여 데이터의 비정형 공구명을 표준화하는 LLM+RAG 파이프라인(RAG v2 Improved, gemma4:e4b)은 **88.5%** 정확도를 달성하였다. 본 포스터는 이 결과에 대한 두 가지 추가 분석을 보고한다: (1) 더티데이터 11개 유형별 정확도를 휴리스틱 분류로 분석하여 취약 유형과 우수 유형의 메커니즘을 규명하고, (2) RAG를 제거한 LLM-only Zero-shot 실험으로 RAG의 순수 기여도를 정량화하였다. 핵심 결과: LLM 단독 정확도는 9~27%에 불과하며, RAG가 **+61~70pp**를 기여한다. 일본어 잔재 유형(47.1%)이 최대 약점으로 동의어 사전 보강이 필요하다.

---

## 1. 배경

- RAG v2 Improved (BGE-m3-ko 임베딩 + BM25/FAISS 하이브리드 + k=15 + 카테고리 주입) 적용 결과: **88.5%** 달성 (gemma4:e4b)
- 이번 분석 목표:
  - **"어떤 유형에서 잘 맞히고, 어떤 유형에서 틀리는가?"** → 더티데이터 유형별 정확도 분석
  - **"RAG 없이는 얼마나 되는가?"** → LLM-only Zero-shot 비교 실험

### 2.4 메커니즘 해석

**오탈자 우수(93.8%) 이유:**
- BGE-m3-ko 1024차원 음절 임베딩이 1글자 철자 오류에서도 의미 벡터를 근접하게 인코딩
- BM25 음절 unigram/bigram이 오탈자-표준명 간 공통 n-gram 존재 시 스코어 부여
- 예: "경랑몽키" → "경량몽키렌치" (자음 오기), "스판너" → "스패너" (모음 오기)

**일본어 잔재 취약(47.1%) 이유 — 3중 장벽:**

| 실패 원인 | 내용 |
|----------|------|
| 임베딩 실패 | "기리" ↔ "드릴비트": 음운 완전 단절, 벡터 분리 |
| BM25 완전 불일치 | 공통 음절 n-gram 0개 → 어휘 검색 무력화 |
| LLM 지식 부재 | RAG가 후보에 포함시켜도 LLM이 매핑 불가 |

> 전체 오답 52건 중 일본어 잔재 오답이 **9건(17.3%)** — 비율(4.6%) 대비 오답 기여 최대

## 3. LLM-only 비교 실험

### 3.1 실험 설계

- **LLM-only**: RAG 없이 LLM 자체 지식만으로 표준명 자유 생성 (Zero-shot)
- 동일 GT 457건, 4개 모델 대상
- 평가 지표: exact match (완전 일치) / nearest match (표준명 리스트 가장 유사 항목 매핑 후 일치)

### 3.2 결과 비교표

| 모델 | LLM-only (exact) | LLM-only (nearest) | RAG v2 Improved | RAG 기여 |
|------|:---:|:---:|:---:|:---:|
| gemma4:e4b | 27.4% | 63.2% | **88.5%** | **+61.1pp** |
| gemma3:4b | 23.0% | 60.8% | **84.5%** | **+61.5pp** |
| exaone3.5:7.8b | 9.4% | 60.4% | **79.2%** | **+69.7pp** |
| deepseek-r1:1.5b | 0.0%* | 0.7% | **78.4%** | **+78.4pp** |

> *deepseek-r1:1.5b: 한국어 자유 생성 능력 근본 부재. 출력이 중국어·영어 혼합. 0%는 API 실패가 아닌 **모델 한계**의 올바른 수치.

### 3.3 유형별 RAG 기여 (gemma4:e4b 기준)

| 유형 | LLM-only | RAG | 기여 |
|------|:---:|:---:|:---:|
| 동력원 명시 | 8.0% | 96.4% | **+88.4pp** |
| 오탈자 | 21.9% | 93.8% | **+71.9pp** |
| 브랜드 혼입 | 28.2% | 87.5% | +59.3pp |
| 일본어 잔재 | 19.0% | 47.1% | +28.0pp |

### 3.4 핵심 발견 3가지

**발견 1 — RAG = 표기 앵커 (단순 보완이 아닌 표기 결정자)**

```
exact(27%) vs nearest(63%) → 35pp 괴리
```

LLM은 "드릴"이라는 개념은 안다. 그러나 "전동드릴"인지 "충전드릴"인지 표기를 결정하지 못한다. RAG가 후보 풀을 제공하면 비로소 정답 표기로 수렴한다.

**발견 2 — 언어 한계 우회**

deepseek-r1:1.5b는 한국어 자유 생성 자체가 불가(exact 0%, nearest 0.7%). RAG 적용 시 **78.4%** 달성. 불가능한 작업을 실용적 수준으로 전환하는 RAG의 극단적 사례.

**발견 3 — 일본어 잔재 RAG 역효과 가설 기각**

LLM-only 19.0% → RAG 47.1% (**+28pp**). RAG는 도움이 된다. 47.1%가 낮은 근본 원인은 LLM 지식 부재이며, 해결책은 RAG 제거가 아닌 동의어 사전 보강.

## 4. 결론 및 시사점

### 주요 결론

| 항목 | 결과 |
|------|------|
| RAG 기여도 | **+61~70pp** — LLM 단독(9~27%)은 실용 불가 수준 |
| RAG의 역할 | 정밀도 보완이 아닌 **표기 결정자 (표기 앵커링)** |
| 최강 유형 | 오탈자 93.8% — BGE-m3-ko 음절 임베딩 덕분 |
| 최약 유형 | 일본어 잔재 47.1% — 3중 실패 구조 |

### 개선 우선순위

| 우선순위 | 대상 | 현황 | 방법 |
|:--------:|------|:----:|------|
| 1 | 일본어 잔재 | 47.1% | 동의어 사전 추가 (기리→드릴비트, 함마→해머 등) |
| 2 | 기타 유형 | 66.7% | Human-in-the-Loop 큐잉 |
| 3 | 영문/약어 | 82.5% | BM25 영문 서브워드 토크나이저 병렬 적용 |

### 시사점

- **유형 기반 오류 분석**으로 개선 우선순위를 특정할 수 있다 — 전체 정확도 집계만으로는 발견 불가한 인사이트
- RAG 파이프라인이 언어 생성 능력 자체가 부재한 소형 모델도 실용 수준으로 끌어올린다는 점은 **엣지 디바이스 배포** 가능성을 시사
